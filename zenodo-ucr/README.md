# ExplainTS: Time Series Classification & Post-hoc Explanations Benchmark

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.18892817.svg)](https://zenodo.org/records/18892817)

This repository contains the source code for generating, managing, and evaluating the **ExplainTS** benchmark. ExplainTS is a comprehensive dataset providing pre-trained deep learning models (ConvLSTM1D) and an extensive suite of post-hoc explanations (LIME, Deep SHAP, Anchor, and PHAR) for multiple datasets from the UCR/UEA Time Series Classification Archive.

The actual datasets, pre-trained models, and precomputed explanation artifacts are hosted on Zenodo:  
👉 **[ExplainTS Zenodo Repository](https://zenodo.org/records/18892817)**

---

## 📂 Repository Structure

The codebase is organized into four main directories, perfectly aligning with the experimental pipeline described in our paper:

### `notebooks/`
Jupyter notebooks containing the core experimental and educational pipelines:
* **`ExplainTS_CaseStudy.ipynb`**: An educational case study demonstrating how to load artifacts and calculate XAI stability metrics without retraining.
* **`UCR-train.ipynb`**: Handles the preprocessing of UCR/UEA datasets and the training of `ConvLSTM-based` baseline models.
* **`UCR-explainers-lime-shap.ipynb`**: Generates continuous feature attributions using Time Series adapted versions of **LIME** and **Deep SHAP**.
* **`UCR-explainers-anchor.ipynb`**: Extracts native rule-based explanations using the **Anchor** algorithm.
* **`UCR-explainers-phar.ipynb`**: Performs extraction and hyperparameter optimization for **PHAR** (Post-hoc Attribution Rules).
* **`datasets_summary.ipynb`**: Extracts dataset statistics and calculates base model accuracies.

### `services/`
Infrastructure scripts used to manage GPU memory and parallelize computationally expensive explanation jobs (specifically for the Anchor algorithm):
* **`model_manager.py`** & **`model_server.py`**: Flask-based REST APIs designed to manage and serve TensorFlow models via Docker.
* **Job-listing utilities**: Simple tools used to orchestrate parallel explanation jobs.

### `results/`
* **`data_and_model_evaluations.csv`**: A summary file generated by `datasets_summary.ipynb`, containing the properties of the datasets, train/test split sizes, and base model accuracies.

### `scripts/`
Bash utilities used for dataset assembly, validation, and packaging:
* **`compress_models.sh`** & **`compress_explainers.sh`**: Scripts for packaging models and individual XAI artifacts.
* **`filter_move.sh`**: Validates the completeness of the generated artifacts and organizes the directory bundles.
* **`compress_all.sh`**: Creates the final `.zip` archives deployed to Zenodo.
* **`report.sh`**: Generates coverage and completeness statistics.

## 🚀 Getting Started

If you simply want to **use the benchmark** to evaluate your own XAI metrics or rule-fusion algorithms, you **do not** need to run the generation pipeline. 
1. Download the artifacts from [Zenodo](https://zenodo.org/records/18892817).
2. Check out the **`notebooks/ExplainTS_CaseStudy.ipynb`** notebook for a quick-start guide on how to load and parse the models and explanations.

### Replicating the Generation Pipeline
If you wish to replicate the training or explanation generation from scratch:
1. Ensure you have Docker installed (required for TensorFlow Serving via `services/`).
2. Install the necessary Python packages (`tensorflow`, `shap`, `lime`, `flask`, `aeon`).
3. Start the model server using the scripts in the `services/` directory.
4. Execute the notebooks sequentially: `Train -> LIME/SHAP -> Anchor/PHAR`.
